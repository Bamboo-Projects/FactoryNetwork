## 10. Bebilderte Anleitung („Ponder“-artig)

**Was der Spieler davon hat:** Zu einem Stichwort öffnet sich eine Seite mit
Code links und dem passenden Aufbau als 3D-Szene rechts.

**Beispiel:** Im Editor auf `round_robin` → F1 → Guide-Seite mit Code und
drehbarer Szene: eine Truhe, drei Öfen.

**Andockstellen:** Der Guide läuft über GuideME (`compat/guide/FnGuide.java:35`),
das 3D-Szenen aus Strukturdateien schon kann. Genutzt wird das bisher nicht
(keine `GameScene` in `guide/*.md`). Neu sind Strukturdateien je Szene und ein
Sprung vom Editor zum Stichwort.

**Größe:** M für statische Szenen; animiert (Ware wandert) L+, weil GuideME
das nicht bietet.

**Offene Frage:** Reichen statische, drehbare Szenen? Empfehlung: ja, zuerst
statisch.

## 1. Gegenstände nach Datenkomponenten auswählen

**Nutzen:** Ein Filter trifft „nur verzauberte Schwerter“ oder „Bücher mit Mending“, nicht mehr jedes `item:diamond_sword` gleich.

**Beispiel:**
```
worker sortieren { from eingang to buecher  filter item:enchanted_book enchanted:mending }
worker reparatur { from lager to amboss  filter tag:c/tools damaged > 50% }
```
Strg-Klick im Terminal kopiert `item:diamond_sword enchanted:sharpness` in den Editor.

**Andocken:** `Parser.parseSelector` (core/.../lang/parse/Parser.java:1430) bekommt nachgestellte Bedingungen als neuen `Expr`-Knoten neben `Except`/`Amount` (lang/ast/Expr.java:130). `ItemSelection.resolve` (main/.../runtime/ItemSelection.java:44) bleibt bei Arten; die Bedingung wird erst nach `KeyedItems.narrow` (network/link/KeyedItems.java:22, Aufruf WorkerRuntime.java:528) als Prädikat auf `ItemKey.components()` (storage/ItemKey.java:109) geprüft. So läuft der Lagerindex weiter nach Art, nur die wenigen Varianten werden einzeln geprüft.

**Aufwand:** M. Parser, Prädikat-Auswertung und Terminal-Strg-Klick sind drei getrennte Stücke.

**Offene Frage:** Darf eine Komponenten-Bedingung auch ohne Artangabe stehen (`filter enchanted`), obwohl das jede Art im Lager prüft? Empfehlung: ja, mit Hinweis im Analysator statt Verbot.

## 2. Hallen-Ereignisse

**Nutzen:** Eine Halle reagiert auf Besuch: Licht und Maschinen an, wenn jemand drin ist, aus, wenn sie leer ist.

**Beispiel:**
```
on hall_entered(halle, spieler) { redstone(lampen, 15) }
on hall_empty(halle)            { redstone(lampen, 0) }
```

**Andocken:** Konstanten und Stelligkeit in `BuiltinEvents` (core/.../lang/BuiltinEvents.java:61). Auslösen in `HallDoor.enter`/`leave` (hall/HallDoor.java:28, :67) über `ControllerBlockEntity.fireEvent` (block/entity/ControllerBlockEntity.java:2803). Empfänger ist der Controller, dessen Netz die Tür oder einen Port der Halle enthält; Hallenname aus `Halls.Entry.name` (hall/Halls.java:55). `hall_empty` braucht zusätzlich Tod, Abmelden und Dimensionswechsel ohne Tür (Spieler-Ereignisse).

**Aufwand:** S. Der Ereignisweg steht; neu ist nur die Zählung der Spieler je Halle.

**Offene Frage:** Spielername als Argument mitgeben? Empfehlung: ja, als Text, damit `where`-Filter auf Personen möglich sind; `hall_left` je Spieler zusätzlich.

## 13. Hallen vergrößern

**Spieler:** Ein Upgrade am Hallenblock macht 16 → 32 → 48; alles Gebaute bleibt stehen.

**Beispiel:** Rechtsklick mit „Hallenerweiterung“ auf den Hallenblock → Tier steigt, Wände wandern nach außen, Spieler drinnen bleiben, wo sie sind.

**Andockung:** hall/HallTier.java:11; Halls.java:161 (Ursprung ist die Ecke, Wachstum nur nach +x/+y/+z, Abstand 1024 reicht); Halls.java:191 `buildRoom` prüft nur `low` und baut bei stehender Hülle nichts → eigene Methode `growRoom`: alte Fern-Wände (x/y/z = alt+1) entfernen, neue Hülle setzen. Ports auf den drei Fernseiten (HallPorts.java:44) an die gleiche Stelle der neuen Wand versetzen; Ankunft (Halls.java:166) neu rechnen; Tickets `HallLoading.force` (HallLoading.java:111) mit altem Tier lösen, neu setzen. Tier im Entry (Halls.java:55) und HallBlockEntity mitziehen.

**Aufwand:** M (Port-Umzug und Ticketwechsel sind die Fallstricke, nicht die Wände).

**Offene Frage:** Item als eigenes Upgrade oder Hallenblock höherer Stufe draufklicken? Empfehlung: größerer Hallenblock als Upgrade, kein neues Item (Textur nötig sonst, Rückfrage).

## 3. Live-Werte und Haltepunkte im Editor

**Nutzen:** Mit der Maus über `storage.count(item:iron_ingot)` stehen sieht man den aktuellen Wert; ein Haltepunkt hält einen Ablauf an, bis man „Weiter“ drückt.

**Ablauf:** Klick auf den Zeilenrand in Monaco setzt einen roten Punkt, der Ablauf bleibt dort mit Status „angehalten“ stehen, Hover zeigt die lokalen Variablen des Frames.

**Andocken:** Monaco schickt Nachrichten über `window.fnSend` (resources/.../web/ide/app.js:36), angenommen in `EditorSession` (client/EditorSession.java:75), weiter per Paket zum Server. Auswerten über `Interpreter.evaluate` (core/.../runtime/Interpreter.java:804), aber nur seiteneffektfreie Ausdrücke (Lesezugriffe, keine `move`/`click`/Zuweisung). Haltepunkt: `FlowEngine` lässt den Ablauf vor dem Schritt stehen statt `flow.resume()` (runtime/flow/FlowEngine.java:395); Variablen aus `Flow.stack()` (flow/Flow.java:95).

**Aufwand:** L. Neue Pakete hin und zurück, Prüfung auf Seiteneffekte, Monaco-Hover und Haltepunkt-Speicher.

**Offene Frage:** Hält ein Haltepunkt auch nach Serverneustart (Abläufe werden gespeichert)? Empfehlung: nein, Haltepunkte gehören zur Editorsitzung, beim Schließen läuft alles weiter.

## 11. Rezepte aus JEI übernehmen

**Spieler:** Werkbank-Rezepte kennt das Netz schon ohne Muster (guide/fertigung.md, „Keine Muster-Items“). Der Nutzen liegt bei **fremden Maschinen**: JEI-„+“ schreibt die passende `recipe`-Zeile ins Programm, statt sie abzutippen.

**Beispiel:** Im Editor offen, JEI-Rezept des Brechers, „+“ → eingefügt wird `recipe crusher_1 at <Gerät> { in 1 item:iron_ore  out 2 item:iron_dust }`; `at` steht als Platzhalter markiert, das Terminal meldet beim Übernehmen, wenn er fehlt.

**Andockung:** compat/jei/FactoryNetworkJeiPlugin.java:50 (`registerRecipeTransferHandlers`, universell für CodeScreen), Text einfügen über client/screen/CodeEditor.java bzw. Monaco; Format wie DeclaredRecipes.java.

**Aufwand:** M (universeller Transfer-Handler + Einfügen in zwei Editoren).

**Offene Frage:** Soll „+“ im Terminal-Fertigungsreiter stattdessen direkt `craft()` bestellen? Empfehlung: beides, Editor = Zeile, Terminal = Bestellung.

## 5. Welt-Verben: abbauen, setzen, benutzen, angreifen

**Beispiel:**
```

```

**Andocken:** Neben `WorldHost.clickAt` (runtime/WorldHost.java:88), das schon einen `FakePlayer` an den Connector setzt (:98). `break` über `player.gameMode.destroyBlock`, damit Schutz-Mods das `BreakEvent` sehen; Drops über die Lagerübergabe in `Handoffs` (runtime/Handoffs.java:48) ins Netz, Rest fällt in die Welt. **Aufwand:** M. `clickAt` liefert das Muster; je Verb ein Weg plus Drop-Behandlung.

**Offene Frage:** FakePlayer je Netzbesitzer (Schutzrechte des Besitzers) oder ein gemeinsamer? Empfehlung: je Besitzer, sonst bauen Spieler über Claims hinweg ab.
